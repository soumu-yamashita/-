# チーム向けタスク管理アプリ 要件定義書

- バージョン：1.1
- 更新日：2026年11月16日
- 対象：初期リリース
- 変更：ユーザー指定により、招待制ログインからログイン不要の公開共有モードへ変更

## 1. コンセプトと利用範囲

「誰が・何を・いつまでに行うか」を共有し、担当の曖昧さと期限漏れを減らすタスク管理アプリ。

主な想定利用者はチームメンバーとリーダー。単一の共有ワークスペースを扱い、URLを知っている人は誰でも全タスクを閲覧・登録・編集・完了にできる。社内メンバーだけに制限する認証は設けない。

担当者名はタスクの割り当て先であり、操作している利用者の本人確認には使わない。ログイン・ログアウト・招待・パスワード設定と「自分のタスク」は提供しない。担当者フィルターで必要なタスクを確認する。

## 2. 最小機能

| 機能 | 要件 |
|---|---|
| 直接アクセス | `/`でログインなしにタスク一覧を開ける |
| 登録 | タイトル・担当者・期限が必須。詳細説明は任意。未完了で登録 |
| 一覧 | タイトル・担当者・期限・状態を表示。初期表示は未完了・期限の近い順 |
| 詳細・編集 | 内容を確認し、タイトル・説明・担当者・期限を変更できる |
| 完了管理 | 完了・未完了を切り替えられる |
| 絞り込み・検索 | 担当者、状態、タイトル検索を組み合わせられる |
| 期限超過 | 未完了かつ日本時間で当日より前の期限を文字と色で示す |
| 進捗表示 | 未完了・当日期限・期限超過件数と全体の完了率を表示 |
| 再取得 | 手動およびブラウザーへのフォーカス復帰で他の人の変更を取得 |
| 操作結果 | 保存成功、入力エラー、通信失敗、版の競合を区別する |

## 3. 入力・業務ルール

- タイトルは前後空白を除いて1〜100文字。空白のみ不可。
- 詳細説明はプレーンテキスト、最大5,000文字。
- 担当者は新規割り当て可能な担当者から1名。担当者未登録時は一覧を表示し、新規タスク登録は無効にする。
- 期限は時刻を持たない有効な日付。過去日も可。期限当日・完了済みは期限超過にしない。
- 同一期限では作成日時の新しい順、さらにID順で並べる。1ページ50件。
- 保存処理中は二重送信を防ぐ。失敗時は入力を保持する。
- 版を照合し、他の人の変更を黙って上書きしない。競合時は最新データを取得し、編集し直す。
- 完了日時はDBで設定し、未完了への復帰でクリアする。
- 担当停止後も既存タスク・担当者名を保持し、内容編集・完了・再割り当てを許可する。
- タスクの削除、操作した人の特定・更新履歴は初期リリースに含めない。

## 4. 画面

- タスク一覧：ナビゲーション、進捗サマリー、絞り込み・検索、登録導線、ページ切り替え。
- 登録モーダル：タイトル・詳細・担当者・期限の入力と保存。
- 詳細・編集モーダル：内容の確認・変更、完了切り替え。
- チームメンバー：担当者と未完了件数の確認。選択すると担当者で絞り込む。
- ヘルプ：登録・編集・完了の操作方法。
- 未設定・通信失敗時：接続案内と再試行。正常な空一覧とは区別する。

旧 `/login`・`/password`・`/auth/confirm` は一覧へ移動する。旧認証APIは提供しない。

## 5. データと技術構成

| 領域 | 採用技術・方針 |
|---|---|
| 画面・API | Next.js App Router、TypeScript |
| UI | Tailwind CSS、Radix Dialog、CVAによるButton |
| データベース | Supabase PostgreSQL |
| 接続 | サーバーからPublishable key / anon keyを使用。認証Cookieを使わない |
| アクセス制御 | RLSを有効にし、全員へ参照と専用RPC実行を許可 |
| 公開先 | Vercel、Node.js 24 |
| テスト | Playwright、Node.jsテスト、実PostgreSQLでの結合テスト |

profilesに担当者、tasksにタスクを保存する。担当者にAuthアカウントは不要。新規タスクのcreated_byはNULLで、旧データの作成者は保持する。詳細は [DB設計](database-design.md) を参照。

## 6. 非機能・運用要件

- 日本語、日本時間（Asia/Tokyo）、PC主体でスマートフォンにも対応。
- Chrome・Edge・Safariの最新安定版を対象にする。
- キーボード操作、フォームラベル、文字による状態・エラー表示を提供する。
- 初期想定は担当者50名、同時利用10名、タスク10,000件。通常の回線で初期50件表示と保存応答を原則3秒以内にすることを目標とし、公開前に計測する。
- 通信は本番HTTPS。管理者用キーはアプリで使わず、秘密値をGitやログへ出力しない。
- 一般利用者はテーブルへの直接書き込みや削除、担当者の管理を行えない。公開RPCで入力検証と版照合を強制する。
- 担当者の追加・新規割り当て停止は管理者がSupabaseで行う。
- アプリは公開共有モードであり、URLの秘匿や送信元チェックを本人認証とみなさない。
- 本番運用前にクラウド利用規定、バックアップ・復元手順、連絡先を確認する。

## 7. 受け入れ条件

1. 新しいブラウザーでもログイン画面を経ず一覧を取得できる。
2. 登録→編集→完了→未完了への復帰ができ、再取得後も保持される。
3. 別ブラウザーで同じ共有タスクを取得・編集できる。
4. 不正な必須項目・文字数・日付・担当者を拒否する。
5. 担当者・状態・検索条件、期限超過、50件を超える表示が正しい。
6. 保存失敗時に入力が残り、保存中の再送信を防げる。
7. 同じ版への並行更新は片方だけ成功し、他方は競合となる。
8. anonロールで参照・RPC実行は可能だが、直接の更新・削除は拒否する。
9. 担当者にAuthユーザーが不要で、停止済み担当者の既存タスクを保持できる。
10. 旧ログイン・パスワードURLが一覧へ移動する。

## 8. 後回しにする機能

削除・アーカイブ、通知、コメント・添付、変更履歴、カンバン・カレンダー、リアルタイム同期、繰り返し・サブタスク・複数担当者、優先度・ラベル、複数チーム、レポート、外部連携、担当者管理画面。

Supabaseへの適用・実接続とVercelへの公開は、環境設定・認証・通信許可の準備後に行う。コードの実装完了と実環境での稼働確認は区別する。
